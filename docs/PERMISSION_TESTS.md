# 权限检查

## 用一个测试账号检查

在「用户管理」创建专用账号。先分配查看者角色，再换成研究员、管理员，每次修改后重新登录。测试完恢复普通角色。

| 检查内容 | 应看到的结果 |
| --- | --- |
| 普通用户打开用户管理、举报审核、权限管理 | 需要对应授权；不能通过修改网址进入 |
| 给一个用户单独禁止某项功能 | 其他用户不受影响；菜单和接口都限制这一功能 |
| 给一个用户单独允许某项功能 | 只开放指定功能，不自动开放其他模块 |
| 修改角色、权限、密码或账号状态 | 原有登录失效，需要重新登录 |
| 设置使用期限 | 到期后原有登录和新登录都被拒绝 |
| 退出登录后重用旧凭证 | 请求被拒绝 |
| 用另一个账号访问私有笔记、AI 记忆或训练任务 | 无法读取或修改；管理员也不能冒用资料所有者 |
| 普通组员修改成员权限或读取其他群的资料 | 请求被拒绝 |
| 临时限制到期 | 恢复原有授权，不增加角色权限，不重新启用停用账号 |

管理员角色提供完整的管理权限。普通角色即使被委派了管理类权限，创建账号、调整角色、共享密钥和账户安全设置仍有最高管理员检查。群组的管理权限也单独检查。

只有实验权限还不足以完成上传流程：上传样本需要文件上传权限，查看模型运行状态需要模型查看权限。缺少权限时，页面会说明需要开放什么。

## 自动检查

Windows，在项目目录运行：

```powershell
.\mvnw.cmd -B -Dtest=PermissionMatrixIntegrationTest,AccountSecurityIntegrationTest,ModerationIntegrationTest test
npm.cmd run test:ui --prefix cle
npm.cmd run build --prefix cle
```

Linux / macOS 把第一条的 `mvnw.cmd` 换成 `./mvnw`，把 `npm.cmd` 换成 `npm`。

权限矩阵会逐个检查全部 35 项权限的单独允许和禁止，验证 44 个受保护接口，并检查查看者、研究员和管理员。测试使用专用资料，不发送收费 AI 请求或真实邮件。

GitHub 的 Verify 工作流会额外使用独立 MySQL 检查权限矩阵、账号安全和举报处罚。要在本地运行这些数据库检查，按 [数据库说明](../database/README.md) 配置临时测试数据库；没有配置时，这部分会明确标记为跳过。测试库使用随机名称，与运行中的业务数据分开。

本次实际执行的结果见 [验证记录](VALIDATION.md)。自动检查能发现已覆盖场景的回归；新增功能、外部服务或新的部署环境需要继续验收。
