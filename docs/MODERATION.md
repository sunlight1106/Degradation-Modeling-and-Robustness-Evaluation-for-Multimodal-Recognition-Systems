# 举报、审核与处罚

## 用户怎样举报

在联系人私聊、群组讨论或收到的站内信下方点击「举报」，填写具体原因，再提交。只能举报自己有权看到的消息，不能举报自己的消息。同一用户对同一条消息只需举报一次，每天最多提交 30 条。

在右上角「目录与账户 → 举报与处罚记录」查看进度。提交后会保存消息原文快照，后续撤回不会抹掉已经提交的证据。被举报人看不到举报人的身份。

## 审核员怎样处理

用管理员账号登录，打开「目录与账户 → 系统管理 → 举报审核」。本机新增的 `check` 账号拥有与 `admin` 相同的管理员权限，专门用于这项工作。它有自己的密码和身份码。初始密码只保存在本机的私有文件里，不随 GitHub 上传；在新部署上可以通过「用户管理 → 新建用户」创建 `check` 并选择管理员角色，没有内置通用密码。

1. 在「待审核」列表选择举报，阅读举报理由和消息快照。
2. 选择驳回、警告、禁言、限制指定功能或封禁。
3. 填写审核理由。需要处罚时，另填时长并选择分钟、小时或天；最长 365 天。
4. 点击「确认审核决定」。同一举报只能完成一次审核，其他审核员随后提交会收到已处理提示。

| 处理方式 | 用户受到什么影响 |
| --- | --- |
| 驳回 | 不增加处罚；解除该举报产生的临时禁言 |
| 警告 | 保存认定理由，不限制功能 |
| 禁言 | 不能发送私聊、群聊和站内信；仍能阅读已有会话和学习 |
| 限制指定功能 | 暂停所选的聊天、群组、笔记、背单词、AI、训练、上传或识别实验入口，服务端也会拒绝对应请求 |
| 封禁 | 不能使用平台功能，仅保留查看本人处罚、申诉和退出登录 |

处罚到期后自动失效，不需要定时任务修改账号。角色、原有的单独禁止、账号停用和注销状态不会被处罚到期覆盖。审核员可填写理由提前解除，记录会保留。不能处理针对自己的举报或解除自己的处罚；不能使最后一个可用管理员失去管理能力。

群主仍可以撤回群内消息，但平台处罚必须交由有举报审核权限的账号处理。需要委派其他审核员时，管理员可在权限管理中授予「审核举报、处罚与申诉」权限；该权限不会允许创建管理员或修改管理员账号。

## 申诉与临时处理

受到处罚的用户在「举报与处罚记录」查看原因和截止时间，并提交一次申诉。审核员切换到「待处理申诉」，阅读情况，填写回复后选择接受并解除或驳回。每次决定都有处理记录。

自动处理仅匹配极少量完整、明确的直接威胁表达，先临时禁言 30 分钟，再交给审核员复核。同一条消息最多触发一次临时处理，其他人重复举报不会重新禁言，也不会覆盖人工审核决定。普通辱骂、争议、引用和语境不明的内容不按关键词直接封号。系统不会调用外部 AI 审核聊天，也不会自动永久封禁。

## 升级

拉取新版本后运行 `deploy.ps1 -Build`，或按部署文档执行 Docker 构建更新。V33 会新建举报、处罚和处理记录表，并把旧群组举报加入统一列表。原有用户和学习数据保留。

证据记录属于平台数据库，纳入现有完整备份。公开部署前应根据自己的运营要求设置账号权限、备份保护和证据保留期限；目前没有自动清除已审核证据的任务。
