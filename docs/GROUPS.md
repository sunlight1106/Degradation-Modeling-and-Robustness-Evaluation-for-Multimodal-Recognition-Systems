# 群组协作与站内信

群组适合围绕论文、项目或实验交流。它沿用已有工作空间，升级后不用重新建立原来的组。

## 建群并邀请成员

1. 登录后打开顶部「目录与账户 → 群组协作」。
2. 研究员点击「新建群组」，输入名称并创建。创建者成为群主；可创建多个群组。
3. 选择群组，展开「成员与权限」。
4. 在「添加成员」选择已有平台账号，选择「成员」并点击「添加」。被添加者刷新群组列表即可看到本群。
5. 在「发布到群组」输入内容，点击「发送到群组」。分享资料可选择附件；只有附件时会自动添加“分享资料”说明。

建群需要平台的 `workspace:manage` 权限，研究员默认拥有。加入群组后，成员访问该群不依赖建群权限。平台管理员可以查看和协助管理所有群组。

## 讨论、回复和资料

- 在某条消息右上角点击「回复」，输入内容后发送；回复会记录原消息关系。
- 每条消息最多 5 个附件，每个不超过 20 MB，支持类型由已有内容检查规则决定。伪造扩展名、可执行内容和病毒扫描不通过的文件会被拒绝。
- 点击资料名称下载。服务器每次检查当前群成员资格和阅读权限，附件没有公开永久地址。
- 点击「刷新」查看最新消息。每次加载 50 条，可点击「查看更早的消息」。当前版本不使用实时推送。
- 成员加入后可以查看本群历史消息与资料；不适合让新成员只看加入后的消息。

## 群角色与平台角色是两回事

| 群角色 | 读取 / 下载 | 讨论 / 发资料 | 成员管理 | 提升群管理员 |
| --- | --- | --- | --- | --- |
| 群主 | 可以 | 可以 | 可以 | 可以 |
| 群管理员 | 可以 | 可以 | 可添加、调整、移除普通成员和只读成员 | 不可以 |
| 成员 | 可以 | 可以 | 不可以 | 不可以 |
| 只读成员 | 可以 | 不可以 | 不可以 | 不可以 |

群角色只影响本群，不能据此访问平台用户管理、角色配置或其他群组。群管理员不能修改群主或其他群管理员。已有自定义群权限可以收窄权限，但不能超过对应群角色的范围。

有成员管理权限的用户可查看添加成员所需的账号名称；普通成员不能读取平台邀请目录。只读成员在成员列表中只能看见自己。

## 站内信与联系管理员

1. 打开「目录与账户 → 站内信箱」。
2. 点击「联系管理员 · 姓名」，或点击「写信」选择收件人。
3. 输入主题、正文，按需添加附件，点击「发送消息」。
4. 收件人在收件箱打开消息，点击「回复这封信」即可回复。

所有启用账号，包括没有其他业务权限的自定义角色，都能联系平台管理员；管理员也能回复或联系所有启用账号。拥有群内阅读和发言权限的用户，可以私信同组有阅读权限的成员。只读成员仍能联系平台管理员。无共同群组的普通用户不能互发，停用账号和本人不在可选收件人中。每封信最多 20 位收件人。

群消息在群组页面查看，私人站内信在收件箱 / 已发送查看。历史私信仍按原收发双方的访问关系保留，不因退群而删除。

## 退出、移除与权限收回

- 非群主成员可点击「退出群组」；群主不能直接退出自己的群组。
- 群主或有相应权限的群管理员可移除成员。退出或移除后，该用户不能继续从服务器读取群消息、发送消息或使用旧群附件链接。
- 服务器校验群组、消息和附件的对应关系；改请求里的群 ID、消息 ID 或附件 ID 不会得到另一群组的访问权。
- 群消息不会出现在私人「已发送」列表，原发件人退群后也不能借此继续阅读群历史。
- 已经下载到成员电脑或复制出去的内容无法撤回。

## 部署与验证

按根目录 README 的更新步骤重建 Docker 镜像。后端自动应用 `V13__group_messages.sql`：为旧消息增加可空的群组和回复字段，保留已有私信、群组和成员，不重建用户数据。

后端 `GroupCommunicationIntegrationTest` 覆盖普通账号联系管理员、组内交流与资料、只读限制、退群和移除后的访问撤回、跨群回复、群角色提权和附件检查。`MySqlSchemaMigrationTest` 验证升级数据、外键与索引；前端 `groups-ui.mjs` 验证回复对象、重复提交、只读界面和切换账户 / 群组时旧响应不会覆盖当前内容。
